# 전체 원본 등록 계약 source_registry v1

`python -m sic_xrt_data_tools.source_registry --source <원본 폴더> --output <새 결과 폴더>`

Area가 서로 다른 웨이퍼라는 사용자의 확인이 있을 때만
`--area-group-basis user_confirmed_distinct_wafers`를 지정합니다. 기본값은 미확정입니다.

원본 전체를 읽고 이미지 전체 페이지를 디코딩합니다. 대용량 ZIP 구성원은 임시 파일,
3D TIFF는 페이지 단위로 처리합니다. 새 결과 폴더는 원본 밖에 있어야 하며
기존 결과 폴더를 덮어쓰지 않습니다. 원본과 임시 추출 파일을 결과에 복제하지 않습니다.
전체 원본에 SHA-256을 검사 전후 두 번 계산하며, 각 ZIP 구성원은 SHA-256·전체 읽기 CRC로
검사합니다. 전체 검사 종료 시 파일 목록/크기/수정 시각도 다시 확인합니다.
실패한 구성원이 있어도 나머지 자료의 등록을 계속합니다.

## 산출물

| 파일 | 의미 |
|---|---|
| registry.json | 계약 이름·버전, 실행 시각, 검사 범위·상태·집계 |
| assets.jsonl | 원본 파일/ZIP 구성원/중첩 구성원 각각의 참조·해시·메타데이터 |
| relationships.json | 동일 바이트 중복, Area 그룹, 이름 기반 촬영·3D 그룹 후보 |
| content_groups.json | 동일 바이트 묶음과 대표 참조 (물리 시료 중복 판정 아님) |
| issues.json / 확인_필요_목록.csv | CRC·디코딩 실패, 명칭 충돌, 방향 변환 필요 등의 목록 |
| 전체_원본_목록.csv | 조회용 원본 전체 목록 |
| 전체원본_등록결과.html | 로컬 검토 보고서 |
| output_hashes.json | 위 기록 파일들의 SHA-256 (자기 자신은 제외) |

`asset_id`는 상대 참조 경로와 ZIP ordinal 경로로 만든 ID입니다. ZIP의 중복된 이름도
개별 항목으로 보존합니다. 다른 위치의 동일 바이트 파일은 각각 등록하고 중복 관계를 별도로
표시합니다. ID는 내용 해시와 다르며, 같은 경로의 내용이 바뀌면 SHA-256 비교가 필요합니다.
압축을 풀어 둔 복사본도 모두 등록합니다. 보고서 Area 영상 수는 ZIP 구성원 기준이고,
전체 등록 수와 동일 바이트 내용 수를 함께 기록합니다. 대표 참조는 ZIP 구성원을 우선하지만
다른 원본 참조나 라벨 이름을 삭제/통합하지 않습니다.
원본 루트 및 메타데이터는 로컬 자료입니다. 실제 산출물은 Git에 넣지 않습니다.

## 해석과 호환성

이미지는 원시 픽셀 좌표계입니다. EXIF 방향은 기록만 하고 좌표/영상에 적용하지 않습니다.
Before/After 이름이 경로 안에서 충돌하면 단계는 `unknown`입니다. `x100`은 이름의 힌트이며
측정 배율이나 µm/pixel이 아닙니다. ImageJ unit과 TIFF resolution으로 계산 가능한 XY 스케일은
확인 전 후보값이고, DPI는 물리 스케일로 사용하지 않습니다. 깊이 간격이 없으면 `missing`입니다.
ImageJ ROI의 타입·좌표 수·경계·기존 클래스/세부 이름을 보존하며 영상 연결/물리적 정답을
추론하지 않습니다. `annotation_origin=supplied_file`은 파일 출처이며 전문가 검수 증명이 아닙니다.

`confirmed` 동일 바이트 중복은 물리적 동일 결함이나 서로 다른 형식의 동일 시야를 뜻하지 않습니다.
전후 영상 이름·그룹이 같아도 정합/결함 대응은 미완료입니다. 디코딩 성공은 파일이 읽힌다는 뜻이며,
시각적 촬영 품질·가짜 대비·정답 라벨 검사는 별도입니다. 판독 오류 항목은 원본을 보존하고
다음 단계에서 제외/재확보/검수 여부를 결정합니다. 미표시 영역을 정상으로 만들지 않습니다.

`completed_with_issues`는 모든 바이트 등록을 끝냈지만 읽기/명칭/방향 이슈가 있는 상태입니다.
해시/CRC 검사 실패, 검사하지 못한 구성원, 원본 변경은 `incomplete`이고 CLI 종료 코드가 1입니다.
파싱 오류와 픽셀 디코딩 실패는 등록 기록에 남는 품질 이슈이며 단독으로는 등록 미완료를 뜻하지 않습니다.
한 파일은 최대 8 GiB, 중첩 ZIP 깊이는 3, 영상은 최대 5억 픽셀로 제한합니다.
TIFF 페이지는 최대 20억 요소를 허용합니다. 제한 초과는 기록에 남으며 의미 검수 완료를 주장하지 않습니다.

`validate_registry(output)`는 기록 파일 해시, ID 중복, 전체 수, 관계 참조를 검사합니다.
원본 자체 재검사는 별도 실행이 필요합니다. 기존 point_dataset v1과 독립 계약이며
라벨·train/val/test 분할·학습 코드를 변경하지 않습니다.

`refresh_registry_reports(output)`는 기록 파일의 유효성을 먼저 검사한 후 같은 원본 등록
기록으로 보고서/바이트 집계를 다시 생성합니다. 원본 재검사나 새로운 정답 검수가 아닙니다.
